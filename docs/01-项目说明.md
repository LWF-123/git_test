# 项目说明

## 1. 题目与边界

门诊挂号与排队叫号系统。只做门诊场景：选科室 → 选医生排班 → 挂号取号 → 候诊叫号 → 完成接诊。不做住院、医保结算、药品库存等扩展业务。

| 约束 | 做法 |
|---|---|
| 纯 Java SE + 控制台 | 只用 `java.*`，界面为文本菜单与表格 |
| 必须使用数据库 | MySQL 8 + JDBC，手写 DAO，SQL 只在 `dao/impl` |
| 体现 OOP | 分层 + 接口 + 责任链 + 枚举承载行为 |
| 并发场景 | 挂号抢号源、叫号取队首 |
| 异常处理 | 自定义异常体系 + 全局兜底 + 局部提示后继续 |

## 2. 分层

```
ui        控制台界面：菜单、输入、表格输出
service   业务编排、事务边界、规则链
dao       SQL、参数绑定、结果映射
domain    实体、枚举、视图对象（含自身行为）
config / common / context   横切支撑
```

## 3. 数据结构（9 张表）

```
department ── doctor ── doctor_schedule ── registration ── queue_ticket
                                              │
patient ──────────────────────────────────────┘
                                              └── visit_record（就诊记录，预留）

sys_user（登录，ref_id 指向 patient/doctor）   operation_log（审计）
```

关键约束：

- `doctor_schedule(doctor_id, work_date, period)` 唯一 → 一个医生同一时段只有一个排班。
- `queue_ticket.registration_id` 唯一 → 一张挂号单只有一张排队票。
- `registration.status` 与 `queue_ticket.status` 同步更新，同处一个事务。

## 4. 核心流程

### 4.1 挂号

```
PatientView.register
  → RegistrationService.register(patientId, scheduleId, type)
    → inTransaction {
        1. ScheduleDao.lockForUpdate            -- 锁住该排班
        2. schedule.isOpen() ?                  -- 停诊/满号直接拒绝
        3. RegistrationDao.findActive           -- 是否已挂过
        4. RegistrationRuleChain.check          -- QuotaRule + DuplicateRule
        5. ScheduleDao.tryIncreaseQuota         -- UPDATE ... WHERE quota_used < quota_total
        6. RegistrationDao.nextQueueNo          -- 同排班内排队号递增
        7. RegistrationDao.insert + QueueDao.insert
      }
```

三层防护：规则链给可读的失败原因；条件更新保证并发下不超号；事务保证“号源、挂号单、队列票”一致。

### 4.2 叫号

```
DoctorView.callNext
  → QueueService.callNext(scheduleId)
    → inTransaction {
        QueueDao.lockFirstWaiting   -- WHERE status='WAITING' ORDER BY priority, queue_no LIMIT 1 FOR UPDATE
        QueueDao.updateStatus(CALLING)      -- 同时写 called_at
        RegistrationDao.updateStatus(CALLING)
      }
```

排序规则：`priority` 升序（急诊 10 → 专家 15 → 普通 20），同优先级按排队号。

过号、完成接诊同样在一个事务里更新两张表的状态。

## 5. 异常处理

| 异常 | 语义 | 表现 |
|---|---|---|
| `ValidationException` | 输入不合法 | 提示具体字段 |
| `AuthException` | 登录失败 | “用户名或密码错误” |
| `BizException` | 业务规则拒绝 | 号源已满 / 重复挂号 / 不在队列 |
| `DataAccessException` | 数据库错误 | 提示检查 MySQL 与配置 |
| 其他 | 未预期 | “系统内部错误，见 logs” |

局部捕获在 `LoginView` 与 `Menu`，全局兜底在 `GlobalExceptionHandler`。

## 6. 设计模式

| 模式 | 位置 |
|---|---|
| 责任链 | `RegistrationRule` → `QuotaRule`、`DuplicateRule` |
| 模板方法 | `JdbcHelper` 的 query/update/inTransaction |
| 策略（预留） | 挂号类型费率（当前由 `RegistrationType` 枚举承载） |
| 工厂（预留） | 排班/挂号单对象创建与默认值 |

## 7. 后续扩展点

| 扩展 | 落点 |
|---|---|
| 退号 | `registration` 状态改 CANCELLED + `quota_used - 1`，同事务 |
